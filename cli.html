Command-line reference

Every command in gameRobotics, with examples. The page docs/cli.html is generated from this file by scripts/build-pages.py; scripts/check-docs.py fails if a command or flag in the code is missing here. Exact behaviour (what play checks, every health message) is in the engine spec, spec.md §0.

Quick start

cd gamerobotics
bin/gamerobotics setup lexjr        # once: builds gamerobotd, makes the Python environments
bin/gamerobotics play lexjr         # the sim, the daemon, the camera and the app; Ctrl+C stops all

You need uv and Rust. setup tells you if either is missing. The first play asks for camera access for your terminal.

gamerobotics

The command most people use. bin/gamerobotics needs only uv the first time: it makes a small Python environment for itself in .venv.

gamerobotics play

Run a project: its processes start in order, each when the one before is ready, and they stop together.

bin/gamerobotics play lexjr
bin/gamerobotics play lexjr --personality attentive-owl
bin/gamerobotics play lexjr --headless --no-camera --seconds 20
bin/gamerobotics play pantilt                    # the 2-DOF pan tilt, same daemon and app
bin/gamerobotics play rover                      # the two-wheeled rover: it turns to look and drives to keep its distance
flagwhat it does
--personality NAMEa personality from the project (curious-cat, shy-puppy, attentive-owl) or a path to a file; default: the project's
--headlessno sim window (the sim still runs)
--no-camerarun without the webcam; the robot looks straight ahead
--seconds Nstop after N seconds
--verboseshow every process's output as it happens, and a status line every 5 s

While it runs, it prints each problem it finds, with what to do, and "fixed" when it clears. It also prints a status line every 15 s:

  loop 50 Hz · 3.7 ms a tick · skipped 0.0/s · camera 27 fps · face yes · CPU 100%

It stops everything on Ctrl+C, when the sim window is closed, or when any process stops. Each process's output is kept in .runs/<date-time>/<process>.log (the last 10 runs).

In the camera preview: m switches the gaze between smooth follow and cat gaze, c makes your current distance the normal one, and q quits the camera.

gamerobotctl

Talk to a running gamerobotd from a terminal: for checking, and for moving joints by hand. Angles are in degrees on this command line, and radians everywhere else.

target/release/gamerobotctl info                        # joints, limits, rate, what it drives
target/release/gamerobotctl enable                      # torque on; holds the pose it's in
target/release/gamerobotctl joints neck_pitch=20 head_yaw=-15
target/release/gamerobotctl watch --hz 5                # state, five times a second
target/release/gamerobotctl disable                     # torque off
commandwhat it does
infothe robot: name, rate, joints with limits and speeds, the IO and kinematics in use
stateone state frame (mode, positions, targets, tick time, skipped ticks)
enabletorque on; the robot holds the pose it is in
disabletorque off
joints name=deg …move joints to these angles (joints mode)
watchprint state frames as they come; --hz sets the rate (default 5)
flagwhat it does
--socket PATHthe daemon's socket (default /tmp/gamerobotd.sock, or GAMEROBOTD_SOCKET)
--hz Nfor watch: frames a second

play runs a daemon for you; gamerobotctl works alongside it.

gamerobotd

The daemon: the robot's 50 Hz loop. play starts it, so you only run it yourself to drive the robot directly or to develop the daemon.

target/release/gamerobotd --io fake                     # a robot that tracks perfectly
target/release/gamerobotd --io sim                      # the simulator on 127.0.0.1:7600
flagwhat it doesdefault
--robot FILEthe robot filerobots/lexjr.toml
--io fake|sima perfect fake robot, or a simulator over TCPfake
--sim ADDRthe simulator's address, for --io sim127.0.0.1:7600
--sim-timeout-ms Nhow long to wait for the simulator each call before reconnecting2000
--socket PATHthe API socket/tmp/gamerobotd.sock
--kinematics native|mujocothe gaze kinematics; mujoco needs a build with --features mujoconative

Test scripts

Run from the gamerobotics directory.

scripts/golden.sh

Exports each robot's golden data from lexjr-sim (LexJR, then the pan tilt), then runs gr-motion's and gr-control's tests against it. Run it after changing gr-motion or lexjr-sim's motion Python.

scripts/golden.sh

scripts/trial.py

Runs one robot end to end: its simulated body (headless), gamerobotd and the face follow app, with synthetic faces instead of the camera. With the app stopped, it then sends look_at targets past the robot's limits. It checks positions against the limits, target speed per tick (a wheel's speed and acceleration), gaze wobble on a held face, and missed ticks. On a wheeled robot it also checks the approach against what keeping the distance asks (within 2 cm) and the daemon's odometry against the body's true pose (body_server --truth-log, within 1 cm and 1°). Then it prints JSON and PASS or FAIL. It uses its own ports and socket (body 7698, faces 5098, /tmp/gamerobotd-trial-<pid>.sock), so it can run beside a live demo.

../lexjr-sim/.venv-bam/bin/python scripts/trial.py pantilt
../lexjr-sim/.venv-bam/bin/python scripts/trial.py lexjr --gaze smooth --hold 5
../lexjr-sim/.venv-bam/bin/python scripts/trial.py rover --hold 4
flagwhat it does
lexjr|pantilt|roverthe robot
--gaze smooth|cat|bothwhich gaze behaviours to run (default both)
--hold Sseconds each synthetic face holds still (default 3; LexJR settles in about 5)
--json FILEalso write the results here

scripts/stress.py

Stresses gamerobotd's API, loop and simulator link. Each test starts its own daemon on its own socket, and a fake body on port 7699.

python3 scripts/stress.py              # every test
python3 scripts/stress.py flood stalled
python3 scripts/stress.py --list

The LexJR processes (lexjr-sim)

play runs these with the right settings. Run them by hand only to work on one of them. Each runs from the lexjr-sim directory with its own environment.

Which robot: each runs LexJR unless LEXJR_ROBOT names another robot file, relative to lexjr-sim, for example LEXJR_ROBOT=pantilt/robot.toml .venv-bam/bin/python body_server.py (rover/robot.toml for the rover). A project sets it in its [env]. lookat.py refuses the rover: it drives servos to angles, and a wheeled robot needs gamerobotd's diff drive.

body_server.py

The simulated body: MuJoCo, LexJR's servo models, and the viewer.

.venv-bam/bin/mjpython body_server.py            # with the viewer
.venv-bam/bin/python body_server.py --headless
flagwhat it does
--headlessno viewer
--host, --portwhere gamerobotd connects (default 127.0.0.1:7600)
--viz-portUDP port for the face and gaze line to draw (default 7610)
--truth-log PATHwrite the true base pose after every read (JSON lines {"t", "pose": [x, y, heading]}), to check a wheeled robot's odometry against; never sent to the daemon

In the viewer: ] gives the side view, and Esc returns to the front view.
