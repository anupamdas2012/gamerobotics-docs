A0 · Addressable API: everything reachable by address

The key rule: every client (CLI, dashboard, later a remote one) talks to APIs by address and never depends on running locally. Then LexJR on the Mac to a Pi walker is a new address, not a rewrite.

  • gamerobotd: the same JSON-RPC over a WebSocket, localhost by default, next to the unix socket
  • Runner control API in the app: slots and owners, switch a behaviour, live parameter changes, load or save a personality
  • Supervisor status API in play: processes and their state, health messages, start and stop
  • The CLI uses these APIs (gamerobotctl and gamerobotics), so it is the first client
  • Jitter histogram in the daemon's state: tick period p50, p99 and worst, over the last minute
  • Guardrails: API servers on their own threads; one state encode a tick shared by all subscribers; slow clients drop frames; no video, meshes or logs on the control API; the runner's control API on its own thread
  • Measure: tick time and jitter unchanged with the dashboard subscribed at 20–50 Hz and intents streaming at 50 Hz
  • Tests: every dashboard action is possible through the APIs alone
